# Educates UDS package

UDS/Zarf package for the minimal Educates 3.8.0 spike profile. It installs the platform directly from manifests generated by Educates' official renderer, plus the pinned Contour and Kyverno dependencies. Consumers do not install or execute the Educates CLI.

## Build

```bash
uds zarf package create educates/packages/platform \
  --architecture arm64 \
  --skip-sbom \
  --confirm
```

Set the package value when deploying to the wildcard DNS parent routed to Contour's LoadBalancer address:

```bash
uds zarf package deploy zarf-package-educates-arm64-3.8.0-uds.0.tar.zst \
  --set-values domain=educates.example.com \
  --confirm
```

## Regenerate upstream manifests

The committed manifest is generated from the official multi-architecture Educates CLI container, not a host binary:

```bash
./scripts/render-manifests.sh
```

The input in `config/installer.yaml` uses Educates' custom infrastructure provider so Contour receives its own LoadBalancer rather than claiming host ports 80/443. This lets it coexist with UDS Core's Istio gateways.

## Current boundary

All runtime images needed by the initial workshop are included in the Zarf package, so deployment does not depend on the Educates installer bundle or a host Educates binary. Optional Educates features such as vcluster, alternate language environments, per-session registries, and remote access are not yet included for air-gapped use.

The package has not completed live UDS Core integration or `validate-package`. Pepr exemptions, Contour/Istio coexistence, Kyverno/Pepr admission interaction, wildcard DNS, and deterministic removal remain live-cluster validation gates.
